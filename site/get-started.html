Get started

Installing the plugin, setting up a repository, and what a first session looks like.

Requirements

  • Claude Code.
  • bash, git and Node 18 or later. The hooks and the installer use Node to read JSON.
  • Linux or macOS.

Nothing has npm dependencies.

1. Install the plugin

Do this once per machine. From a shell:

claude plugin marketplace add redazzo/Yotamake
claude plugin install yotamake@yotamake

Start a new Claude Code session afterwards. The skills show up as yotamake:simple-session, yotamake:multi-session and so on.

2. Set up a repository

Open Claude Code inside the repository and run:

/yotamake:setup

It runs the plugin's installer, then reads the repository and proposes the project facts: the check commands, the branching rules and the Architecture lines. It asks before it commits anything.

You can also run the installer by hand from a clone of the Yotamake repository:

./plugin/install.sh /path/to/your/repo

The repository's .claude/settings.json then names the Yotamake marketplace and enables the plugin. Teammates who open the repository in Claude Code are prompted to install it.

Other hook tools. If the repository has a .pre-commit-config.yaml, a lefthook config or a hook in .git/hooks/, the installer leaves core.hooksPath alone, so that tool keeps working. It prints the lines that call .githooks/pre-commit from your tool instead.

If the repository already has its own version of a template file, such as a docs linter, list the path in .claude/yotamake/skip, one per line. The installer never writes a listed path.

What gets installed

FileWhat it does
CLAUDE.mdThe project facts the skills read, in named sections.
scripts/checkThe one gate. Skills, the pre-commit hook and CI all run it.
.githooks/pre-commitRuns scripts/check --staged, the fast checks only.
.github/workflows/check.ymlCI runs scripts/check --all.
.claude/settings.jsonEnables the plugin, adds the ask rules for commit, merge and push, and two SessionStart hooks.
.claude/yotamake/Protected paths, per-file checks, the skip list, the installed version, and the two session scripts.
docs/, scripts/docs/The docs system and its linter. Left out in lite mode.

Some of these files belong to your project and are copied only when missing. Others belong to the harness and are refreshed on every run. The installer never overwrites a project-owned file. How it is split lists which is which.

3. Fill in the facts

/yotamake:setup does most of this for you. Whatever it cannot work out is left as a FILL IN placeholder in CLAUDE.md. The sections the skills read are:

  • Checks: how scripts/check works, and whether to write tests first.
  • Branching and releases: the main branch, branch prefixes, merge or pull request, version bumps, and which files count as docs.
  • Architecture: Style, Modules, Boundaries, Shared code, Patterns and Constraints.
  • Migrations and Deploying: only if the project has them.
  • Conventions: anything else Claude should follow.

A skill that finds a section missing says so and uses a stated default, or stops and asks. It never guesses a deploy or migration command.

Then open scripts/check and add your project's checks: type-check, lint, tests. Put slow ones behind full so the pre-commit hook stays fast.

Lite mode

For a small repository that does not want ADRs, records and a backlog:

./plugin/install.sh /path/to/repo --lite

Or ask /yotamake:setup for lite mode. You get CLAUDE.md, scripts/check, the pre-commit hook, the hook config and the settings, but nothing under docs/. You can add the docs system later. The README says how.

4. Your first session

Ask for a change as usual. There is no need to name a skill. Claude picks simple-session for any edit to code, tests or docs, and works through it:

> Rename the --out flag to --output and keep --out as an alias

It cuts a branch, makes the change, updates the doc that owns it, runs scripts/check and a review, and then asks whether to commit and merge. See a session, step by step.

For a new feature where "done" is unclear, agree the scope first:

/yotamake:spec

For work too big for one context, Claude offers a multi-session plan. It writes the plan to a working folder that survives /clear. Between sessions you clear the context and resume with:

> Read .scratchpad/<folder>/README.md and start the next session.

Or say "run autopilot" once the plan is approved, and the remaining sessions run on their own. It ends with one report and asks once before merging.

Check the setup

/yotamake:doctor

A read-only check: the pre-commit hook, the harness version and pending upgrades, FILL IN placeholders left in CLAUDE.md, whether scripts/check runs any project checks, and whether CI runs it. It prints one screen with a fix for each problem.

Updating

claude plugin update yotamake@yotamake

This updates the method for every repository at once. To refresh a repository's harness-owned scripts, re-run /yotamake:setup in it.

When a new version needs a line added to a project-owned file, such as CLAUDE.md, Claude tells you at the start of the next session and offers to apply it.

The plugin also includes a plain-english output style, which keeps Claude's replies short and plain. Select it with /output-style.
