Skills

The skills, grouped by what they are for. Each card links to the skill's SKILL.md, which has its full rules.

automatic skills run when a request fits; there is no need to name them. manual skills run only from their slash command, such as /yotamake:setup.

Making changes

simple-session

automatic

Runs any change to code, tests or docs as one session: size check, branch, design and reuse, the work and its doc, scripts/check, review, then stop and ask before commit. Used for every change, even a one-line fix.

Reads: Checks, Branching and releases, Architecture.

Read SKILL.md →

multi-session

automatic

Plans and runs work too big for one session as numbered sessions, with a working folder that survives /clear. Covers parallel sessions in worktrees and autopilot.

Starts when a change is too big for one session, or when you say "start the next session".

Read SKILL.md →

debugging

automatic

A bug fix inside a session. Reproduce the bug, write a failing test, find and name the root cause rather than patching the symptom, then fix it and see the test pass.

Does not branch, commit or review. The session around it does.

Read SKILL.md →

spec

/yotamake:spec

Agrees what a new feature must do before any code: scope, non-goals and numbered acceptance criteria in one short spec.md. Asks one question at a time, challenges words that clash with the glossary, then hands over to a session.

Fixes, renames and refactors skip it.

Read SKILL.md →

improve-architecture

/yotamake:improve-architecture

Reviews the design of existing code, starting where git history shows it changes most. Finds shallow modules worth deepening, places where the code and the Architecture section disagree, and code names that clash with the glossary, rates them, and names the one to do first. Read-only.

Reads: Architecture and the glossary. Proposes new terms. Hands the chosen candidate to a session, the backlog or an ADR.

Read SKILL.md →

Docs and diagrams

write-doc

automatic

Adds or changes a doc under docs/. Picks the kind (reference, guide, decision or record, or a backlog entry), names and places the file, writes it from the template for its kind, links it, and runs the docs linter.

Setup, releases and migrations

setup

/yotamake:setup

Installs the per-repository files, or refreshes them after a plugin update. Then helps fill in CLAUDE.md and scripts/check from the repository itself, and applies any pending upgrades.

Read SKILL.md →

doctor

/yotamake:doctor

Checks the harness works in this repository: the pre-commit hook, the version and pending upgrades, FILL IN placeholders, whether scripts/check runs real checks, whether CI runs it, and whether project.conf agrees with CLAUDE.md. Read-only.

Read SKILL.md →

release-check

/yotamake:release-check

Guides a deployment to the right target and component, with a pre-flight checklist and the project's known gotchas. Refuses to guess a command when CLAUDE.md has no Deploying section.

Reads: Deploying.

Read SKILL.md →

new-migration

/yotamake:new-migration

Scaffolds a database migration file with the right timestamp and sequence number, and reminds you how to apply it locally and remotely.

Reads: Migrations.
