Yotamake

A Claude Code plugin that sets up a repository so Claude works on a branch, runs the project's checks before it proposes a commit, and asks before committing, merging or pushing.

What it does differently

Many coding-agent harnesses are prompts and conventions alone, which work only while the model follows them. Yotamake has those too, plus the four things below. The plugin is the same for every repository, and each repository's CLAUDE.md holds the facts it needs: check commands, branch rules and the architecture.

Enforced, not only asked

The stop points and branch rules are hooks and permission rules, so they do not depend on a skill firing or on what is still in context.

Small steps, and you approve what matters

A session is one branch: Claude checks the change fits, makes it, updates its doc, runs the checks and a review, then stops for approval. Larger work becomes planned sessions that survive /clear: you approve the plan, and they run on their own unless you choose to step through. Nothing reaches the main branch without your yes.

Your architecture, checked first

Before editing, Claude looks for code to reuse and reads your Architecture section and ADRs, not a generic process. A change that would break a boundary or an accepted ADR stops for a decision.

One gate for people, Claude and CI

scripts/check lists every check. Claude runs it before proposing a commit, the pre-commit hook runs the fast checks, and CI runs all of them, so a pass means the same everywhere.

Skills also cover specs, bug fixes, design reviews, deploy checklists and migrations. All the skills.

What the hooks block

What the hooks block and the permission rules stop to ask about, even when no skill runs.

Edits on the main branch

Edit and Write are refused while the repository is on its main branch.

Ending a turn with unchecked code

If code was edited and scripts/check has not passed since, the Stop hook sends Claude back to run it once.

Commit, merge or push without asking

git commit, merge, push, rebase, reset --hard and tag are under ask rules, so Claude Code prompts for each one.

Skipping hooks and editing secrets

--no-verify and git commit on main are refused. Files such as .env and private keys cannot be edited.

The hooks only see the Edit, Write and git commands, so a file written from the shell gets past them. Limits of the hooks.

Install

Install the plugin once per machine, then set up each repository.

Install the plugin

# in a shell
claude plugin marketplace add redazzo/Yotamake
claude plugin install yotamake@yotamake

Set up a repository

# in Claude Code, inside the repository
/yotamake:setup

This installs the repository files and fills in CLAUDE.md and scripts/check from the code. Anyone who opens the repository afterwards is prompted to install the plugin.
