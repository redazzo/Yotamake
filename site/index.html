Claude Code plugin v__VERSION__

A working method for Claude Code, in every repo.

Yotamake is a harness. It makes Claude work in small sessions on branches, check the design before writing code, run one check command, and stop to ask before anything is committed.

The idea

Skills hold the method. Your repo holds the facts.

The plugin is the same everywhere. Each repository says what is specific to it in named sections of its CLAUDE.md, and the skills read them. Update the plugin once, and every repo gets the new method.

01

One session, one branch

A change runs as a session: check the size, cut a branch, do the work, update the doc that owns it, check, review, then stop. Work too big for one context becomes a planned series of sessions.

02

Design before code

Before any edit, Claude looks for code to reuse and reads your Architecture section. If a change would break a boundary or an accepted decision, it stops and asks, even when told not to.

03

One gate for everyone

scripts/check is the only list of checks. Claude runs it before proposing a commit, the pre-commit hook runs its fast part, and CI runs all of it.

Enforced

Not just asked for.

Instructions in a prompt get skipped. Yotamake backs the important ones with hooks and permission rules, so they hold even when a skill does not fire.

No edits on main

A hook refuses Edit and Write while the repository is on its main branch. Claude has to cut a branch first.

No unchecked code at the end of a turn

If Claude edited code and scripts/check has not passed since, a Stop hook sends it back to run the check.

A yes before commit, merge and push

git commit, merge, push, rebase, reset --hard and tag sit under ask rules. Claude Code asks every time, whatever a skill says.

No skipped hooks

A Bash hook refuses --no-verify and git commit on the main branch. Protected files such as .env and keys cannot be edited.

The hooks have known gaps, for example a shell command that writes a file. What the hooks do not cover.

Install

Two steps.

Add the plugin once per machine. Then set up each repository you want it in.

1. Add the plugin

# in a shell
claude plugin marketplace add redazzo/Yotamake
claude plugin install yotamake@yotamake

2. Set up a repo

# in Claude Code, inside the repo
/yotamake:setup

It installs the per-repo files, then fills in CLAUDE.md and scripts/check from what it finds in the repo. Teammates who open the repo are prompted to install the plugin.

Docs that stay true

Four kinds of doc, one owner per subject.

A full install adds a small docs system. Each kind has its own update rule, and a linter fails on broken links, orphaned pages and bad front-matter.
