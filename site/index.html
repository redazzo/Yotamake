Let Claude Code change real code, and stay in charge of it.

Yotamake gives Claude a working method for your repository. It works on a branch, follows your architecture, runs your checks and stops for your yes before anything is committed. Hooks enforce the key rules, so they hold even when a prompt is forgotten.

The problem it solves

A coding agent is fast, but on a real repository speed is not the hard part. The hard part is keeping its changes small, checked, in line with the design, and yours to approve. Instructions in a prompt help until the context fills up or a rule is missed.

Without a methodWith Yotamake
Edits land on main, or in one large change that is hard to review.Every change is one branch with one concern. A hook refuses edits on main.
"Done" is claimed before the tests, lint or types have run.Claude runs scripts/check before it proposes a commit. If it skips that, a hook sends it back once.
New helpers duplicate old ones, and layers call what they should not.Claude looks for code to reuse and checks your Architecture section and ADRs first. A conflict stops for your decision.
Commits, merges and pushes happen without anyone looking.Each one asks first, through Claude Code's permission rules.
Big work loses its thread at the next /clear.A plan you approve, split into sessions with a working folder that survives /clear.

Why it holds up

Many harnesses are prompts and conventions alone, so they work only while the model follows them. Yotamake has those too, plus four things that keep working on a long day in a large repository.

Enforced, not only asked

The stop points and branch rules are hooks and permission rules. They do not depend on a skill firing or on what is still in context.

You approve what matters, and only that

A session is one branch: Claude checks the change fits, makes it, updates its doc, runs the checks and a review, then reports and asks. For larger work you approve the plan once, and the sessions run without stopping between them, unless you choose to step through. Each commit still asks.

Your architecture, not a generic one

Claude reads your Architecture section and ADRs before it edits. A change that would break a boundary or an accepted ADR stops for a decision, even when you said not to ask.

One gate for people, Claude and CI

scripts/check lists every check. Claude runs it before proposing a commit, the pre-commit hook runs the fast checks, and CI runs all of them. A pass means the same everywhere.

The plugin is the same for every repository. Each repository's CLAUDE.md holds its own facts: check commands, branch rules and architecture. Skills also cover specs, bug fixes, design reviews, deploy checklists and migrations. All the skills.

Guardrails that hold without a skill

The hooks block these, and the permission rules stop to ask, even when no skill runs.

Edits on the main branch

Edit and Write are refused while the repository is on its main branch.

Ending a turn with unchecked code

If code was edited and scripts/check has not passed since, the Stop hook sends Claude back to run it once.

Commit, merge or push without asking

git commit, merge, push, rebase, reset --hard and tag are under ask rules, so Claude Code prompts for each one.

Skipping hooks and touching secrets

--no-verify and git commit on main are refused. Claude's Read, Edit and Write tools refuse files such as .env and private keys.

The hooks see Claude's file tools and git commands, not other shell commands, so a file read or written from the shell gets past them. We say so up front: limits of the hooks. Behaviour is tested by an eval suite that scores Claude with the plugin against Claude without it.

Set up in three commands

Install the plugin once per machine, then set up each repository. Setup reads your code and proposes the facts, so you review rather than write them.

Install the plugin

# in a shell
claude plugin marketplace add redazzo/Yotamake
claude plugin install yotamake@yotamake

Set up a repository

# in Claude Code, inside the repository
/yotamake:setup

This installs the repository files and fills in CLAUDE.md and scripts/check from the code. Anyone who opens the repository afterwards is prompted to install the plugin.
